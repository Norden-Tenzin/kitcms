# @kitcms/ui

The kitcms admin: the shell, dashboard, list and edit views, the field components, the block editor, the upload field and the media library. It is Svelte 5 and is rendered by a route file that `kitcms` generates into your app, so there is nothing to build by hand. The admin logic (`load` and form `actions`) lives in `@kitcms/core/sveltekit/admin`.

```sh
pnpm add @kitcms/ui
```

`@kitcms/ui` peer-depends on `@kitcms/core`, `@sveltejs/kit` (v3) and `svelte` (v5).

## Usage

The admin route in an app is generated, and should not be edited. `templates/blank/src/routes/(kitcms)/admin/[...path]/+page.svelte`:

```svelte
<!-- GENERATED by kitcms. Do not edit: the admin lives in @kitcms/ui. -->
<script lang="ts">
	import { Admin } from '@kitcms/ui';

	let { data, form } = $props();
</script>

<Admin {data} {form} admin={adminConfig} />
```

(with `import adminConfig from '../../../../kitcms.admin';` in the script block). The matching `+page.server.ts` re-exports the server side:

```ts
// GENERATED by kitcms. Do not edit: the admin lives in @kitcms/core and @kitcms/ui.
export { load, actions } from '@kitcms/core/sveltekit/admin';
```

## Live preview

Previews are browser code, so they are registered in a client-safe `src/kitcms.admin.ts` (not in `kitcms.config.ts`) and loaded lazily:

```ts
// src/kitcms.admin.ts
import { defineAdmin } from '@kitcms/ui';

export default defineAdmin({
	previews: {
		collections: { pages: () => import('#lib/previews/Page.svelte') }, // props: { doc }
		globals: { site: () => import('#lib/previews/Site.svelte') }, // props: { doc }
		blocks: { hero: () => import('#lib/blocks/Hero.svelte') }, // props: { block, doc }
	},
});
```

- The edit view shows a pane beside the form (stacked on narrow screens) with Hide/Show and Desktop/Mobile (390px) toggles. A collection/global preview takes over the pane; otherwise, if any `blocks` value has a registered block preview, the blocks render in document order (blocks without a preview show a labelled placeholder).
- `doc` and `block` are the **live form state** (a `$state` object, updated on every keystroke). They are **read-only by contract**: never write to them.
- Upload/relationship values are ids. Resolve them with `useRelation('media', () => block.image)`, which returns `{ current, loading }` (a `PickerDoc` with `title`, and for uploads `url`, `width`, `height`). Lookups are batched and cached.
- Previews render inside `.kitcms-preview`, which resets the admin typography and colours (`all: initial`, on a light canvas) so only your component styles apply. Import site CSS from the preview components, scoped (Svelte component styles are).
- Nothing runs on the server: the pane renders a "Loading preview…" placeholder and loads components in the browser. A load or render error shows inline and never breaks the form.

## Exports

From `packages/ui/src/lib/index.ts`:

- `Admin`: the admin app component. The generated route renders it.
- `FieldShell`: the wrapper that field components render inside.
- `fieldId`: builds the DOM id for a field.
- `FieldProps` (type): the props every field component receives.
- `getFormContext`: reads the form context inside a field component.
- `FormContext` (type): the shape of that form context.
- `FileUpload`: the upload control.
- `MediaPicker`: the media library picker used by the upload and relationship fields.
- `defineAdmin`, `useRelation` and the preview types (`AdminClientConfig`, `DocPreviewProps`, `BlockPreviewProps`, `LazyComponent`, `PickerDoc`): live preview (above).
